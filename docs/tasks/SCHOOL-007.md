## 진행·인계

- 상태: 구현 및 검증 완료. 사용자 직접 체감 확인은 미확인.
- 측정 결과: 이동 update는 평균 약 0.01ms. 반복적인 프로젝터 투사 기하 계산은 화면 CPU 제출 중 약 1.0~1.4ms. 거울에서는 같은 기하를 두 번 계산.
- 변경: 프로젝터/칠판 상태가 같으면 투사 면·획을 재사용. 시점과 거울만 움직일 때는 재계산하지 않음. 칠판 애니메이션·프로젝터 방향 변경·초기화는 갱신. 화면 밖 삼각형은 GPU 제출 전 제외.
- 실제 파일: `rooms/school/SchoolRoom.cpp`, `SchoolRoom.h`, `SchoolRenderer.cpp`, `tests/SchoolPerformance.cpp`, `tests/run-performance.ps1`, 학교 README, 이 기록.
- 검증: 학교 Release 빌드, 기존 **474 checks / 0 failures**. 기존 Debug 실행 파일과 수정 Release에서 동일 63개 장면을 숨겨진 OpenGL 창으로 캡처. **62개 픽셀 완전 일치**, `corridor-window-a`만 채널 최대 1/255, 전체 평균 차이 0.000003/255. 거울 반사·공책 힌트·프로젝터 회전·칠판 이동·실물화·복도 포함. OpenGL 오류 없음.
- 환경: RTX 4060, 1280×800, MSAA 4, 최적화 `/O2`, VSync 0, 120프레임 예열 + 600프레임 × 3회. 동일 카메라/입력 경로. CPU update/submit 및 GL_TIME_ELAPSED, glFinish까지 total을 분리 측정.

- 표는 각 통계의 3회 중앙값. 걷기/보기 CPU 평균 약 27% 감소. 거울 회전 p95/p99는 개선되지 않은 측정도 있으므로 모든 끊김 제거를 주장하지 않음. total의 3회 중앙값은 걷기 6.051→2.585ms, 보기 6.922→3.186ms, 회전 6.368→3.558ms. GPU query에는 CPU 제출 공백이 포함될 수 있고 glFinish/숨김 창/OS 스케줄링 영향이 있어 실제 표시 FPS와 구분.
