## 재현 기록 — 수정 전

- 환경: Windows, MSVC v145, C++/OpenGL. 사용자가 실행 중인 `rooms/school/preview/bin/Debug/SchoolPreview.exe`는 2026-11-21 빌드. 종료하거나 UI 입력을 보내지 않고 현재 화면만 확인.
- 기대: 위쪽에 놓을 공간이 없으면 공책이 보이는 손 위치에 남고, E를 눌러도 화면 밖으로 놓이지 않음.
- 실제: 정상 집기 후 눈을 거의 수직으로 올리면 `notebookPlacement`가 시선 밖 바닥의 작은 공책 위치를 반환. E로 그곳에 놓고 들기 상태를 해제함.
- 최소 절차: 최초 공책을 `(-4.83,0,3.8)`에서 정상 집기 → 빈 통로 `(3.8,0,2.4)` → yaw=0, pitch=1.3/1.45/1.54rad → E.
- 수치: 세 각도 모두 배치 중심 `(3.8,0.0759033,1.7)`, 크기 0.474395. 시선과 배치 방향의 내적 -0.771734/-0.858102/-0.900780으로 화면 밖. 2초 후 같은 바닥 위치에 남고 들기 비율은 0. 두 번 동일하게 재현.
- 대조: pitch=1.1에서는 상단 Y=4.499(천장 4.5 아래)에 배치 후 바닥으로 낙하. 크기·높이·위치·각도 56,448조합에서 실제 천장 위 경계 이탈 0건. 사용자 사례와 완전히 같은 원인인지는 미확인; 확인된 사라짐 경로를 먼저 수정.
- 증거: `build/notebook-ceiling-20261122/Probe.cpp`, `probe.log`, `probe-repeat.log` (로컬 진단 산출물, Git 제외).
- 진단: 위쪽 광선 배치가 플레이어와 겹쳐 거절되면, 주변 바닥을 8방향으로 찾는 보조 경로가 현재 세로 시선을 무시하고 작게 옮겨 놓음. 실제 화면은 배치 후보를 표시하므로 E 직전부터 사라져 보일 수 있음.
