# 학교 — 칠판 밖으로 나온 정답

단일 교실 v5 초안을 바탕으로 만든 C++·OpenGL 학교 공간이다. 프로젝터 회전과 계단 실물화 퍼즐을 풀고 자료실 뒤로 걸어 나가면, 복도와 옆 교실 두 개가 이어진다. 가짜 복도를 간파해 2-1 교실 뒷문을 지나고, 미닫이문과 철제 발판을 실물화해 계단실·현관 방향으로 나간다. 교실부터 마지막 출구까지 로딩이나 순간이동 없이 이동한다.

고정된 프로젝터를 회전해 빛에 가려진 칠판 선을 발견하고, 투사된 계단 조각을 다른 그림과 잇는다. 완성된 그림이 특정 시점에서 계단으로 읽히는 상태를 0.4초 유지하면, 0.65초 동안 두께와 그림자가 생기며 자동으로 실물화된다. 이전 거울 암호·도형 순서·프로젝터 초점 맞추기는 제거했다.

## 실행

- 이 PC에서 빌드한 실행 파일: `preview/bin/Release/SchoolPreview.exe`. 같은 폴더의 `glew32.dll`과 `assets/art-class-still-life-v2.png`가 필요하다. 빌드 시 함께 복사된다.
- Visual Studio: [SchoolPreview.slnx](preview/SchoolPreview.slnx)를 열고 `Release | x64` 또는 `Debug | x64`, `Ctrl+F5`로 실행한다.
- 팀 테스트: 최신 `main`의 [Out_of_Scale.slnx](../../project_code/Out_of_Scale/Out_of_Scale.slnx)를 열고 x64로 실행한 뒤 **F1**을 누른다. F2·F3·F4로 기존 구간에 돌아갈 수 있고, 같은 실행 중 다시 F1을 누르면 학교 진행을 이어서 확인한다. 학교를 처음부터 보려면 Esc 후 R. 실행 인수 `--school`로 바로 시작할 수도 있다.
- 팀 솔루션은 기존 정적 GLFW·GLEW 설정으로 빌드한다. 실습용 `glfw3.lib`·`glew32.lib`를 쓰는 PC에서는 MSBuild에 `/p:OpenGLRoot=<실습 OpenGL 폴더>`를 넘긴다. 정물 소묘는 두 솔루션에서 빌드 결과의 `assets`에 복사된다.
- 빌드 전제: Visual Studio C++ v145, Windows SDK, GLFW·GLEW·GLM. 이 PC의 실습용 라이브러리 경로 `%USERPROFILE%\source\libs\OpenGL`을 사용한다. 다른 위치라면 MSBuild의 `OpenGLRoot` 속성을 지정한다.
- 방 메시·한글은 코드와 Windows 맑은 고딕을 사용한다. 정물 소묘는 저장소에 포함한 [PNG](assets/art-class-still-life-v2.png)를 Windows GDI+로 읽는다. 실행 중 외부 다운로드는 없다. 이미지의 [생성 프롬프트](assets/art-class-still-life-v2.prompt.txt)를 함께 보존했다.
- 현재 도구 체인에서 LocalAppData의 개체 파일 변경 후 링크가 생략되는 문제를 재현했다. 학교 프로젝트는 컴파일 캐시를 유지하되 링크는 매번 수행하도록 설정했고, 일반 Build에서도 실행 파일 갱신을 확인했다.

Developer PowerShell에서 다음 명령으로 다시 빌드한다.

```powershell
MSBuild.exe rooms/school/preview/SchoolPreview.slnx /t:Rebuild /p:Configuration=Release /p:Platform=x64
& ./rooms/school/preview/bin/Release/SchoolPreview.exe
```

## 조작

| 입력 | 동작 |
| --- | --- |
| WASD | 시선 방향을 기준으로 이동 |
| 마우스 | 1인칭 시점 회전 |
| 프로젝터를 가까이서 보고 E | 조정 시작 / 마침 |
| 프로젝터 조정 중 마우스 | 프로젝터 좌우·상하 회전 |
| 복도 청소도구함 문을 가까이서 보고 E | 문 닫기 / 열기 |
| 실물화한 미닫이문을 가까이서 보고 E | 미닫이문 열기 |
| Space | 지면에서 점프 |
| Esc | 일시정지 / 계속하기 |
| 일시정지 중 R | 교실·복도 퍼즐과 플레이어를 처음 상태로 초기화 |
| 일시정지 중 Q | 종료 |

다른 창으로 이동하면 자동으로 일시정지하고 프로젝터 조정을 끝낸다. 게임 창으로 돌아와 Esc로 계속한다. 프로젝터에서 멀어지거나 점프해도 조정은 끝난다.

프로젝터와 받침대의 위치는 고정이다. E로 조정을 끝내면 마지막 방향을 유지한다. 계단 생성 전에는 다시 회전할 수 있다. 휠 초점 조작은 없다.

보행은 짧게 가속하고 키를 놓으면 빠르게 감속한다. 최고 속도는 기존 3m/s이며, 정지 시 이동은 검사상 9cm 이내다. 계단을 밟는 몸체 높이는 즉시 반영하고 시점 높이는 짧게 보간해 한 칸마다 화면이 튀는 느낌을 줄였다. 마우스 시점에는 별도 지연을 넣지 않는다. 책걸상 모서리는 원형 발밑 충돌을 사용한다. 청소도구함 문도 시작과 끝에서 가감속하며, 회전 중 접촉 시에는 되돌아간다.

## 방과 퍼즐

교실은 약 13 × 14 m다. 이전 9 × 10 m보다 바닥 면적이 약 두 배이며, 책상 열두 개를 칠판을 향한 3열×4줄로 배치했다. 왼쪽 창가의 목제 거울, 앞쪽 수업 칠판과 교탁, 붙박이 수납장 위의 자료실 단상과 출구가 있다. 책상 사이와 양옆, 앞뒤 통로를 걸어 다니며 관찰한다. 출발점은 뒤쪽 문 앞 `(4.8, 0, 7.6)`이다.

뒤쪽에는 12칸 사물함·시간표·학급 약속판·독서 벤치를, 오른쪽에는 책이 꽂힌 학급 문고·학생 그림 게시판·준비물 수납장을 배치했다. 창가 커튼·화분, 청소장·빗자루·분리수거함·벽 스피커도 추가했다. 책상마다 책·종이·필통·연필·물병·가방을 다르게 배치했다. 장식물은 새 퍼즐이나 상호작용 대상이 아니며, 주요 가구는 충돌을 적용했다.

1. **칠판을 덮은 그림:** 프로젝터가 칠판 세 면 전체에 물병·배·석고 구와 블록·쌓인 스케치북을 그린 연필 정물 소묘를 비춘다. 실제 미술 수업 참고 그림처럼 보이도록 PNG 자산을 사용하며, 그림 안의 퍼즐 보조선은 연하게 표시한다. 칠판 비율에 가까운 가로형 소묘를 사용하고 가장자리까지 종이 색을 투사한다. 물병·배·석고·책 전체가 칠판 안에 들어오도록 그림의 여백과 비율을 맞췄다. 처음에는 칠판의 계단 선이 모두 가려진다. 칠판의 분필 선만 고정되어 있다. 바닥·교탁·수납장에 걸친 아래 계단 획은 전부 투사 그림이며, 소묘와 같은 회전을 따른다. 바닥의 큰 베이지색 도화지·테이프·말린 가장자리는 제거했다. 기존 나무 타일이 투사 영역에도 그대로 이어지고, 초기 바닥에는 고정 계단 윤곽이 없다. 거울은 고정된 반사 소품이다.
2. **회전하며 발견:** 오른쪽 통로의 프로젝터를 가까이서 보고 E를 누른다. 마우스로 회전하면 밝은 영역과 투사 그림이 함께 이동한다. 빛이 지나간 자리에서 원래 칠판 선이 조금씩 드러난다. 반대로 돌리면 다시 가려진다. 특정 진행률에 따라 방 전체 그림을 켜는 타이머는 없다.
3. **그림 연결·자동 실물화:** 프로젝터를 수납장 앞 종이 쪽으로 돌려 투사된 계단 조각이 주변 그림과 이어지게 한다. 정렬은 투사된 선 끝점의 실제 오차로 판정한다. 계단 생성 전에는 방향을 틀면 연결도 풀리며 다시 맞출 수 있다. E로 조정을 마친 뒤 걸으며 전체 그림이 계단처럼 보이는 시점을 찾는다. 시선·착지까지 맞는 상태를 0.4초 유지하면 0.65초의 실물화 연출이 시작된다. 시점이 잠깐 스치거나 인식 도중 벗어나면 인식 시간은 초기화된다. 연출이 시작된 뒤에는 이동·점프·시점 변경이 가능하고 생성은 끝까지 이어진다. 표지처럼 얇은 면이 나무 계단의 두께와 그림자를 얻고, 완료된 뒤 보행 충돌이 켜진다. E로 생성할 필요는 없다. 비활성·일시정지·창 초점 이탈 중에는 인식과 연출 시간이 멈춘다.
4. **보행:** 계단을 올라 자료실 단상과 처음부터 열려 있던 문을 지난다. 프로젝터·계단 생성과 문 잠금은 연결하지 않는다. 실제로 출구에 도달했다면 다른 유효한 경로로 올라왔어도 통과할 수 있다. 계단에서 내려와 다시 교실을 둘러볼 수도 있다.

고정된 계단 그림은 칠판에만 있다. 나머지 획은 프로젝터 회전에 따라 칠판·종이·벽·바닥 등의 실제 표면에 맺힌다. 불투명한 흰 사각 면을 제거하고, 정물 소묘를 투사하고 그림 주변에는 부드러운 빛을 적용했다. 칠판·뒷벽에서 소묘 밖으로 튀어나오던 별도 계단 윤곽은 표시하지 않는다. 칠판·종이의 원래 색이 비치며, 투사선에도 가장자리 흐림과 미세한 명암 변화를 적용했다. 칠판 선의 가림과 소묘 표시는 같은 투사 범위를 사용하고, 선 투사와 판정도 같은 표면 정보를 사용한다. 칠판 영상의 가림은 실제 렌더링 범위와 일치하며, 프로젝터 광원의 가구 그림자는 계산하지 않는다. 방 전체 조명을 계산하는 광학 시뮬레이션은 아니다. 계단 판정은 프로젝터 정렬·칠판 노출과 전체 그림의 투영 오차·시선·착지를 사용한다. 숨겨진 정답 지점과의 거리는 검사하지 않는다. 기본 조작은 시작 직후 잠깐, 프로젝터 안내는 가까이서 바라보거나 조정 중일 때만 표시한다.

높이 차이는 계단 착시를 유지하기 위한 학교 내부 구조다. 단독 받침대 위의 높은 문을 자료 보관용 붙박이장·단상·난간·열린 자료실 입구로 묶었다. 13×14 m 교실과 12석, 기존 생활 소품은 유지했다.

계단의 디딤면 윤곽을 스케치북 표지로 삼고, 바로 아래에 페이지 결·옆면 소묘를 더했다. 페이지 면도 같은 관찰 광선으로 교탁·바닥에 나뉘어 투사되며 프로젝터와 함께 회전한다. 장식용 페이지 선은 시점 정답 판정에서 제외한다. 바닥을 스치는 빛은 입사각에 따라 약해져 나무 타일이 비친다.

세 의자는 조금 빼거나 틀어 놓고 가방과 충돌 범위도 같은 위치를 따른다. 책의 방향, 커튼의 밑단, 게시물 기울기는 일정하지 않게 조정했다. 책상 배치와 퍼즐 관찰 통로는 유지한다.

| [SchoolRenderer.h](SchoolRenderer.h), [SchoolRenderer.cpp](SchoolRenderer.cpp) | 방 전용 OpenGL 렌더러, 투사광 마스크·부드러운 획·표면 혼합, 평면 거울 반사, 한글 텍스처와 HUD |

| [tests/SchoolRoomTests.cpp](tests/SchoolRoomTests.cpp) | 정답·오답, 충돌, 재시작, 반사·투영, 연속 보행 검증 |

- 학교 로컬 좌표는 Y-up, 1 단위 약 1 m, 교실 바닥 Y=0이다. 교실 출구는 X=3.05, Z=-5.0, 바닥 Y=1.8, 진행 방향 -Z다. 유효 폭 약 1.3 m, 문 높이 약 2.0 m다. 자료실 뒤 연결 통로는 같은 높이에서 +X 방향의 복도로 이어진다.
- 복도는 X=2.37~25.1, Z=-11.5~-8.3, 바닥 Y=1.8이다. 마지막 계단실은 0.2m × 6단을 내려 바닥 Y=0.6에 도착한다. 폭 3.65m 점검 구간을 건너 계단을 내려간다. 현관 표지 아래 문을 통과한 X=23.55, Z=-21.85 부근에서 학교 완료를 판정한다. 이후 타 스테이지 연결 후보 기준은 `(23.55, 0.6, -21.95)`, 방향 -Z이며 아직 팀 공통 규격은 아니다.
- 계단 높이 0.3 m × 6단, 단 깊이 0.6 m, 폭 1.8 m다. 보행 속도 3.0 m/s, 눈높이 1.65 m, 반경 0.22 m다.
- 이 수치는 **학교 로컬 규격**이다. 팀 공통 연결 규격으로 합의한 것은 아니다. 군대까지의 실제 복도 연결은 미구현이다.
- `school::Camera`와 방 전용 충돌 코드는 학교 검증용이다. 공용 `Player`를 바꾸지 않았다. 통합 때 담당자와 높이·충돌 전달 방식을 맞춰 어댑터를 연결한다.
- 공용 클래스의 이름·함수·파일 형식·빌드 설정과 상대 담당의 파일은 변경하지 않았다.

## 검증

```powershell
& ./rooms/school/preview/bin/Release/SchoolPreview.exe --self-test
& ./rooms/school/preview/bin/Release/SchoolPreview.exe --capture-dir ./rooms/school/captures
```

- `--self-test`: 기존 교실부터 현관까지 연속 보행, 가짜 복도의 충돌과 실제 교실 뒷문, 문 정렬·실물화·E 입력, 발판의 오답·정답 시점, 도움닫기 우회 차단, 추락 후 복귀, 실물 발판의 지지·초기화를 확인한다. 연속 완주에서는 좌표·퍼즐 상태를 강제로 변경하지 않는다.

## 복도와 계단실

[Superliminal 개발자 Phil Fortier의 공식 기술 설명](https://blog.playstation.com/2020/06/30/breaking-down-the-tech-behind-superliminals-mind-bending-illusions/)의 **Trompe-l’œil**을 참고했다. 한 시점에서 평면이 공간처럼 보이게 하는 경우와, 맞춰 본 그림이 물체가 되는 경우를 구분한다. 학교의 타일·철망 유리·목제 문·철제 난간을 모델과 그림으로 직접 구성했다.

1. **2-1 앞 — 가짜 깊이.** 복도 끝에 형광등과 타일이 이어지는 것처럼 보인다. 다가가 비스듬히 보면 출입문 그림과 타일이 한 벽에 붙어 있다. 옆 2-1 교실의 앞문으로 들어가 실제 뒷문으로 나오면 벽을 돌아갈 수 있다. 접근 기록이나 잠금 해제 조건은 없다.
2. **2-2 뒤 — 그림 문짝.** 청소도구함을 열면 문 그림 조각이 실제 문짝을 따라 회전한다. 몇 걸음 물러나 맞은편 벽 그림과 연결하면 목제 미닫이문이 된다. 지면에서 정렬된 그림을 0.55초 보면 0.75초 동안 실물화한다. 생긴 문은 닫혀 있으며 손잡이 가까이에서 E로 직접 연다.
3. **계단실 — 철제 발판.** 낮은 층과 맞은편 벽에 그려진 줄무늬를 위층에서 내려다본다. 난간 사이로 줄무늬가 한 덩어리로 맞춰지면 철제 발판과 난간으로 바뀐다. 발판을 직접 걸어 건넌다. 아래로 떨어지면 점검 계단으로 올라올 수 있다.
4. 건너편 계단을 내려가 현관으로 나간다. 미닫이문과 발판은 시점을 돌려도 유지된다. Esc 후 R로 교실과 복도를 함께 초기화한다.

참고 시점은 문이 `(15.30, 3.45, -10.70)`, 발판이 `(23.95, 3.45, -10.45)`다. 자유 보행 중 실제 투영 광선의 오차와 가림으로 정렬을 판정한다. 문은 회전판과 벽에, 발판은 아래층 바닥과 맞은편 벽에 투영한다. 생성 결과는 벽이나 바닥을 건너는 데 쓰는 실제 충돌이다. 원근으로 물체 크기를 바꾸는 공통 기능과 최윤서 담당 코드는 수정하지 않았다.
