# 작업 기록 양식

작업별로 docs/tasks/A-001.md 또는 docs/tasks/B-001.md 등에 복사한다. 한 작업의 담당자 한 명이 관리한다. 작업 종료·인계 전에 반드시 실제 파일로 저장한다. 이어서 하는 같은 작업은 이 파일을 갱신한다.

## 작업 시작

- 날짜 / 작업 ID / 제목:
- 담당자:
- 상태: 예정 / 진행 / 인계 가능 / 보류
- 작업 브랜치 / 시작 기준 커밋:
- 확인한 기획서·관련 작업:
- 목표:
- 수정할 파일·폴더:
- 완료 기준:
- 다른 작업과의 의존 관계:

## 진행·인계

- 마지막 갱신일 / 현재 상태:
- 변경 내용과 이유:
- 실제 수정 파일:
- 실행한 검증과 결과:
- 미검증 사항과 확인 방법:
- 공통 약속 변경 / 상대 담당에게 미치는 영향:
- 커밋 전 확인한 상대 작업 기록(공유 브랜치와 경로):
- 남은 문제 / 다음 작업:
- 로컬 커밋:
- 원격 푸시:
- main 통합:

## 날짜별 진행

- YYYY-MM-DD: 변경·결정·검증 내용을 짧게 추가한다. 이전 결정이 바뀌면 이유를 함께 적는다.

## 중요한 AI 활용 사례가 있을 때

- 요청 요약:
- 사람의 검토·수정:
- 결과 확인:

필수 항목에 해당 사항이 없으면 없음 또는 미수행과 이유를 적는다. 검증하지 않은 내용과 사람이 아직 확인하지 않은 내용은 미확인으로 표시한다. 최종 답변에 이 기록의 경로를 포함한다.

작업 파일과 이 기록을 같은 커밋에 넣는다. 푸시 뒤 공유 브랜치, 커밋, 기록 경로를 팀원에게 전달한다. 커밋·푸시·통합은 실제 수행한 상태를 각각 적는다.
