## 진행·인계

- 측정 도구에 해상도·MSAA 인자를 추가했다. 기본 1280×800/MSAA4를 유지하며 통합 게임의 FHD/MSAA0 부하를 비교할 수 있다.
- 초기 숨김 창이 Windows 작업 영역 제한으로 1920×1061로 만들어지는 문제를 확인했다. 숨김 테두리 없는 창을 만든 후 명시적으로 크기를 설정하고 실제 프레임버퍼 크기가 요청과 같을 때만 측정한다. 최초 잘못된 크기의 결과는 최종 비교에서 제외했다.
- `-Configuration Debug`는 `/Od`, Release는 `/O2`를 적용한다. 두 조건 모두 `/MD`, 같은 소스·장면·GPU다. 전체 Visual Studio Debug 환경이나 실제 통합 실행 파일의 표시 FPS를 측정한 것은 아니다.
- 루트 `play-release.cmd`와 `tools/play-release.ps1`을 추가했다. 현재 브랜치의 통합 프로젝트를 Release x64로 Build한 뒤 MSBuild가 반환한 TargetPath를 실행한다. 빌드 실패 시 오래된 실행 파일로 진행하지 않는다. Visual Studio 위치를 vswhere로 찾으며 설치 경로 인자를 지원한다.
- 실행기는 기존 통합 검사와 같은 명령 한정 `WholeProgramOptimization=false`를 사용한다. 큰 기하 소스의 기존 LTCG 도구 문제를 피하는 경로이고 `/O2`는 유지한다. 공용 vcxproj와 사용자가 선택한 Visual Studio 구성은 변경하지 않는다.
- 실제 수정 파일: `play-release.cmd`, `tools/play-release.ps1`, `rooms/school/tests/SchoolPerformance.cpp`, `rooms/school/tests/run-performance.ps1`, `rooms/school/README.md`, `illusion-escape-game-plan.md`, 이 기록.

### 검증·인계

- Temp 폴더에서 루트 CMD를 절대 경로로 `-BuildOnly` 실행해 저장소 위치와 무관하게 Release 빌드가 통과하고 올바른 실행 파일을 찾는 것을 확인했다. 실제 게임 창은 열지 않았다.
- 설치되지 않은 Visual Studio 경로를 전달했을 때 오류와 종료 코드 1을 확인했다. 두 PowerShell 파일 구문, 문서 UTF-8·링크, `git diff --check`를 확인했다.
- 제품 렌더링·퍼즐 C++는 변경 없음. 기존 검증을 반복하지 않고 실행기와 계측 변화에 필요한 검증을 수행했다. 픽셀 비교·새 방 전환 검사는 미수행이다.
- 미검증: 실제 전체화면 표시 간격·VSync·사람의 마우스 체감, 다른 GPU, QHD/4K. 숨김 VSync0 측정은 표시 FPS가 아니다. 이미 Release로 실행 중에도 끊긴다면 다음 단계는 실제 표시 프레임 시간과 VSync/드라이버/백그라운드 부하 측정이다.
- 공통 약속 변경: 없음. 팀원도 선택적으로 실행기를 사용할 수 있으며 게임 시작 위치·전체화면·해상도는 동일하다.
- 커밋 전 공유: `origin/main` 61b0b10, `origin/yoon778` f9611e4의 지침·TEAM·GIT-20261122-01·B-031 확인. 변경 여부를 다시 확인한 뒤 커밋한다.
